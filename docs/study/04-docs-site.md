# 04 — Upstream docs site study (react-advanced-cropper → SvelteKit rebuild)

> Historical study of the upstream implementation and earlier port. Proposed mappings and release observations below are not the 0.2.0 API; see the [current design log](00-index.md) for superseding decisions.

Source studied: `tmp/react-advanced-cropper/example` (upstream commit `a51e293`, 2026-07-26).
The live site (https://advanced-cropper.github.io/react-advanced-cropper/) is still this Docusaurus 2
build. A spot check of `/docs/showcase` matched the source: same sidebar, no search box, no visible
dark-mode toggle, no version dropdown. **The source is authoritative.** Paths below are relative to
`tmp/react-advanced-cropper/example/` unless they start with `tmp/` or `src/`.

---

## 0. TL;DR

- **Stack:** Docusaurus `2.0.0-beta.6` with preset-classic, `docusaurus-plugin-sass`, prism-react-renderer
  (`github` / `dracula` themes), MDX v1 and React 17.
- **Docs:** 50 doc files, 6,446 lines of MDX/MD. 18 of them are 7-line "not documented yet" stubs.
- **Demos:** 1 custom homepage, about 40 distinct demo components, about 4.6k lines of TSX and 2.4k
  lines of SCSS, plus about 46 icon components.
- **No live code.** Every fence is static (`tsx` 198, `ts` 24, `js` 18, `jsx` 16, `scss` 9, `css` 4,
  `shell` 2, `html` 1, untagged ~296 closing fences). Demos are separate React components rendered
  above or beside a hand-written snippet. The snippet often differs from the demo source: different
  image URL, and `useState` noise.
- **Template filler and dead code:**
  - the whole blog
  - `HomepageFeatures.tsx` and `.module.css`
  - `static/img/tutorial/*`
  - `static/img/docusaurus.png`
  - `useQueryState` (so `query-string` is unused)
  - `SomethingShowcase`: imported in `showcase.mdx` but never rendered
  - the `react-mobile-cropper` SCSS import (no `rmc-*` class is used anywhere)
- **react-mobile-cropper does NOT need porting.** The homepage "Mobile Cropper" and the Showcase
  "Telegram" demo are `TelegramCropper`. That component is built on the framework-agnostic core module
  `advanced-cropper/showcase/mobile`, which is already installed (`node_modules/advanced-cropper/showcase/mobile`).
- **Licensing:** demo code is MIT. **Prose, the SVG diagrams/illustrations and the logo belong to
  Norserium.** Photos belong to Unsplash/Pexels authors. See §5.

URL shape: Docusaurus keeps file-name case and drops the extension. For example,
`docs/components/Cropper.mdx` becomes `/docs/components/Cropper` and `docs/guides/advanced-recipes.mdx`
becomes `/docs/guides/advanced-recipes`. The deployed base is `/react-advanced-cropper/`.

### 1.2 Sidebar order (as rendered)

Docusaurus sorts docs and categories together by `sidebar_position` / `_category_.json` `position`.
Ties keep the file-system order. Unpositioned items come last, in file-name order. Result, which
matches the live site:

| #   | Item            | Kind               | Position source                                                   |
| --- | --------------- | ------------------ | ----------------------------------------------------------------- |
| 1   | Getting started | doc `intro.mdx`    | `sidebar_position: 1`                                             |
| 2   | Guides          | category           | `guides/_category_.json` position 2                               |
| 3   | Showcase        | doc `showcase.mdx` | `sidebar_position: 3` (ties with Tutorials; doc wins by FS order) |
| 4   | Tutorials       | category           | position 3                                                        |
| 5   | Components      | category           | position 4                                                        |
| 6   | Hooks           | category           | position 5                                                        |
| 7   | Concept         | category           | position 6                                                        |
| 8   | FAQ             | doc `faq.mdx`      | `sidebar_position: 6` (ties with Concept)                         |
| 9   | Algorithms      | category           | position 7                                                        |

For a SvelteKit rebuild, a hand-written ordered nav array is simpler and more predictable than
re-implementing this tie-breaking (§6.4).

### 1.4 Upstream link debt (don't replicate)

`onBrokenLinks: 'ignore'` hides several dead links:

- Vue-era links: `/components/cropper.html#refresh`, `#setcoordinates-transform`, `#sizeretrictions`,
  `/components/simple-line.html`, `/introduction/news.html#…`
- `/docs/concept/basic/#image` and `#state` (the page is `state`)
- `/docs/guides/#passing-props-to-the-stencil`
- `/docs/guides/recipes#changing-a-stencil` (the heading is "Change the stencil")
- `/docs/components/cropper/#callbacks` and `/docs/components/rectangle-stencil#props` (wrong case)
- `advanced-recipes#default-size-and-position` (the heading is "Position / Size")

"Edit this page" points at `facebook/docusaurus` (template leftover). A rebuild should validate links:
SvelteKit's prerender crawler fails on 404s by default, which is a feature here.

**Svelte:** one `.svelte` file per icon (keeps tree-shaking and parity), or a single
`Icon.svelte` with a `name → path` map. Dedupe the local copies. These icons are part of the upstream
site _design_. They're small geometric glyphs (likely the author's own), so treat them like the other
artwork (§5) and redraw or replace them with an MIT icon set (e.g. Lucide/Tabler) if in doubt.

## 6. Proposed SvelteKit architecture (recommendation)

Project facts that constrain this:

- Svelte `^5.57`, SvelteKit **3.0.x** (Kit options live in `vite.config.ts` `sveltekit({...})`; there's no
  `svelte.config.js`)
- Vite 8, runes **forced** for all non-`node_modules` files via `compilerOptions.runes`
- `adapter-auto` today
- `src/lib` is the published package
- `#lib/*` subpath imports
- no Tailwind

### 6.3 Page metadata

Each page exports `title`/`description` either:

- via `+page.ts` `load` returning `{ meta: { title } }`, which `docs/+layout.svelte` reads through
  `page.data`, or
- from the single `nav.ts` entry keyed by pathname (one source of truth for title, order and pager).

Prefer `nav.ts`.

### 6.4 Sidebar generation

Upstream "autogenerates" from directories, but has ties and two title bugs (§1.3). Use a typed tree
in `src/site/nav.ts`:

```ts
type NavItem = { title: string; href: `/docs/${string}`; stub?: boolean };
type NavGroup = { title: string; items: NavItem[] };
export const nav: (NavItem | NavGroup)[] = [/* order from §1.2 */];
```

`Sidebar.svelte`:

- renders collapsible groups (`<details>` keeps it zero-JS-friendly)
- highlights `page.url.pathname`
- auto-expands the active group

`DocPager.svelte` flattens `nav` for prev/next. A tiny vitest (server project) asserts that every
`nav` href has a matching `src/routes/**/+page.*`, which catches drift. If mdsvex pages appear,
`import.meta.glob('/src/routes/docs/**/+page.svx', { eager: true, import: 'metadata' })` can feed
titles into the same tree.

### 6.5 Headings and TOC

- **`.svelte` pages:** a `<Heading level={2} id="...">` component, or plain `<h2 id>`. The TOC is built
  either from a per-page exported `toc` array or by scanning `[id]` headings in the content element on
  mount. Scanning is client-only, so the TOC appears after hydration. That's acceptable for a
  right-rail TOC, but the inline TOC (`TOCInline` on `Cropper`/stencils/FAQ) should be static. For
  data-driven API pages, derive both from the data array.
- **mdsvex pages:** a ~20-line remark plugin that slugifies headings (`github-slugger`-compatible, to
  match Docusaurus anchors like `#rotate--flip-image`, which existing deep links rely on) and pushes
  them into `metadata.headings`.

### 6.6 "Example + source" blocks

Upstream shows the demo, then a hand-written React snippet (sometimes tabbed TSX/SCSS) that drifts
from the demo. For the rebuild, **show the real demo source**:

- `Example.svelte`: renders a framed demo (`{@render children()}` or `component` prop) with a
  "Show code" toggle or tabs below it. The source is the demo file itself. A Svelte SFC carries its
  own `<style>`, so the TSX/SCSS tabs collapse into one.
- Getting highlighted source **at build time** (Shiki must not ship to the client):
  - **Preferred:** a small Vite plugin in `vite.config.ts` that resolves `import code from './Demo.svelte?highlight'`.
    It reads the file and runs Shiki (`createHighlighter` once, cached) with
    `themes: { light: 'github-light', dark: 'dracula' }`. It exports an HTML string, which
    `CodeBlock.svelte` renders with `{@html}`. Works the same from `.svelte` and `.svx`, and keeps the
    code next to the demo. A `?highlight&lines=10-40` variant can show an excerpt.
  - **Alternative:** `+page.server.ts` with `import.meta.glob('$site/demos/**/*.svelte', { query: '?raw', import: 'default' })`
    plus Shiki in `load`. This is prerendered, so Shiki never ships, but each page needs a server load.
- Keep **hand-written snippets** only where the doc compares variants that aren't separate demos:
  - Function vs Object `defaultCoordinates`
  - Default Position vs Default Size
  - the three CropperPreview approaches
  - Fixed vs Hybrid configs

  Use `<Tabs>` + `<CodeBlock lang="svelte" code={…}>` (a template string highlighted through the
  same Vite plugin by putting snippets in sibling `.svelte`/`.ts` files and importing with `?highlight`).
  This avoids runtime highlighting.

- Inline code fences in mdsvex pages use the mdsvex `highlight.highlighter` hook with the same Shiki
  instance (escape `{`, `}` and backticks for Svelte; mdsvex exports `escapeSvelte`).
- Copy button: `navigator.clipboard.writeText(rawCode)`. The plugin exports both `{ html, raw }`.

### 6.8 Static deployment to GitHub Pages

- Swap `@sveltejs/adapter-auto` for **`@sveltejs/adapter-static` 4.0.0** (peer `@sveltejs/kit ^3.0.0-next.0`,
  so it matches our Kit 3.0.1) with `{ pages: 'build', assets: 'build', fallback: '404.html', strict: true }`.
  GitHub Pages serves `404.html` for unknown paths, so the fallback gives a client-rendered `+error.svelte`.
- `paths: { base: process.env.BASE_PATH ?? '' }` in the `sveltekit({...})` options. In CI set
  `BASE_PATH=/svelte-advanced-cropper` (or derive it from `GITHUB_REPOSITORY`). Locally it's empty.
- `+layout.ts`: `export const prerender = true;`. Keep the default `trailingSlash: 'never'`: it emits
  `docs/intro.html`, GitHub Pages serves `/docs/intro`, and the URL shape matches upstream.
- **All internal links and asset URLs must be base-aware.** Upstream hard-codes
  `/react-advanced-cropper/img/...` in ~45 places. Use `resolve('/docs/intro')` and
  `asset('/img/images/x.jpg')` from `$app/paths`, or a tiny `img()` helper. In mdsvex, absolute
  markdown links/images need a rehype/remark rewrite that prefixes `BASE_PATH`.
- Prerender crawl: every page must be reachable from `/` or listed in `prerender.entries`. The nav
  covers this. `handleHttpError: 'fail'` (default) catches broken links that upstream ignores.
- **SSR safety:** pages are prerendered, so demo components and the library must not touch
  `window`/`document`/canvas during SSR. Upload, `URL.createObjectURL`, `window.open`,
  `context-filter-polyfill` and the hash state all belong in event handlers / `onMount` / `$effect`.
  This also validates that the library itself is SSR-safe.
- `static/.nojekyll` (Jekyll ignores `_app/`).
- GitHub Actions workflow: checkout → `jdx/mise-action` (tools pinned in `mise.toml`) → `pnpm install` →
  `BASE_PATH=/<repo> pnpm exec vite build` (the site only; `pnpm build` also runs
  `svelte-package` + `publint`, which is harmless but slower) → `actions/upload-pages-artifact` (`build/`)
  → `actions/deploy-pages`. Pages source = "GitHub Actions".
- The Playwright e2e config (`pnpm build && pnpm preview`, port 4173) keeps working. Run e2e with an
  empty base, or add a base-path variant.

### 6.9 Homepage specifics

- Hero navbar variant (transparent on `#161515`) and the docs navbar share one `Navbar.svelte`.
- Family switch: "Svelte" (active) | "React" (link to upstream) | "Vue". Credit upstream clearly
  (it's a port).
- The wizard's hash state is read client-side (`$effect` on `page.url.hash`), defaulting to
  `default-cropper` during prerender. Hash writes go through
  `replaceState` from `$app/navigation` (not raw `history.replaceState`, which bypasses Kit's router state).

  icon rows use the drag-scroll attachment.
