# Svelte-native design log and historical studies

This directory records the project's architectural decisions and the studies that informed them. Documents 01–05 describe the historical upstream implementation and earlier port. They are evidence, not the current public API specification.

The 0.2.0 API is defined by the public declarations, executable examples and contract tests. Its design uses Svelte composition while preserving the core's cropping capabilities. Start with [the public exports](../../src/lib/index.ts), [types](../../src/lib/types.ts) and [introduction](../../src/routes/docs/intro/+page.svx).

The historical studies examined react-advanced-cropper at commit `a51e293` (package version 0.20.2) and advanced-cropper 0.17.1. Their version and release observations are snapshots from that study, not statements about current upstream releases.

## Decisions — 2026-10-09, 0.2.0

1. **Settings (D1):** built-in core settings remain flat, typed props. `settings?: E` holds extension settings only; extension keys must not redefine built-in names. The routing keys are checked against the declared props in [cropperProps.ts](../../src/lib/service/cropperProps.ts).
2. **Core exports (D2):** keep the runtime dependency and `export * from 'advanced-cropper'`, plus required extension types. Library imports use only the root and supported `extensions/*` entries to avoid duplicate core loading under SSR. Do not reimplement core algorithms.
3. **Public types and private implementation (D3):** `CropperInstance<E>` is a structural interface, not a constructor. `FixedCropperInstance<E>`, `CropperPreviewInstance` and `CropperPreviewSource` describe the other instance contracts. `CropperSettings<E>` describes normalized settings. Typed snippet arguments use `*SnippetProps` names. The controller, reactive engine, loader, registries, shared view, export canvas and artificial transition are internal. Advanced composition uses `Cropper`/`FixedCropper`, algorithm props, snippets, context and primitives; public `AbstractCropper` and all `use*` exports are removed. Option normalizers are plain `normalize*ImageOptions` functions. `DraggableArea` is the public gesture name; handler/line wrappers use `onMove`/`onMoveEnd`. `CropperSource` stays public with `bind:element`.
4. **Context (D4):** require Svelte `^5.40` for `createContext`. [getCropperContext](../../src/lib/context/cropper.ts) exposes a stable initialization-time API, reactive `disabled` and displayed `image`, and `registerStencil`. Registration automatically installs destruction cleanup and returns an idempotent token-owned disposer. Boundary/source registration belongs to snippets, not public context.
5. **Child stencil lifecycle (D5):** stencils synchronously register option getters before state guards and the first reset. No children supplies a rectangle; supplied children may register zero or one stencil. Multiple live registrations after an update settles throw; nested croppers isolate context. Registration, removal, replacement and reactive option changes reconcile without resetting, including when `autoReconcileState` is false. SSR registers and validates without browser work. Stencil children add guides inside the draggable region; inherited disabled state cannot be overridden. Circle registers ratio and bounding-box shape; FixedCropper retains the core stencil-size strategy. Explicit cropper ratios take precedence under the default constraint strategy; custom strategies receive raw settings before normalization.
6. **Layer snippets (D6):** croppers expose `wrapper`, `boundary`, `backgroundWrapper`, `background`; preview exposes `wrapper`, `boundary`, `background`; stencils/boxes expose `handler` and `line`. Boundaries use `registerBoundary`; export backgrounds attach their actual drawable with `attachSource(ready?)`. [RegistrationSlot](../../src/lib/controllers/RegistrationSlot.svelte.ts) cleanup owns its token, so stale cleanup cannot remove a replacement or revive an older source. Readiness belongs to the current displayed image; canvas-enabled `onReady` waits for its source.
7. **Styling (D7):** one `class` (`ClassValue`) and `style` (string) per public visual component. Removed per-part class props are replaced by stable selectors and state modifiers, including bounding-box handler/line groups. The [styling reference](../../src/routes/docs/reference/styling/+page.svx) and contract tests define this surface. Library components have no `<style>` blocks; [build-styles.ts](../../scripts/build-styles.ts) ships global CSS and themes without scoped specificity.
8. **Instance and callbacks (D8):** preserve all 33 instance methods, including functional/sequential `setCoordinates` and plain-value `setImage`. Callbacks receive the generic instance and run only while mounted; mutation methods and notifications run untracked while getters stay reactive. No public `getInstance` prop. Defer `bind:coordinates`; read with `$derived` and write through constrained methods. Component bindings implement the same interface as the stable callback/context API without promising object identity.
9. **Documentation (D9):** task-oriented guides, composition, reference and core pages use lowercase kebab-case URLs. No legacy redirects, redirect manifest or migration pages. The site documents only the current API, as decided below. The Telegram site demo may import `advanced-cropper/showcase/mobile`; the root/extensions-only rule applies to `src/lib`. Keep supported demos; do not invent unsupported tutorial material.

## Documentation scope decision — 2026-10-09

Do not publish comparisons or migration documentation for other cropper libraries. Credit code derived from Norserium's MIT-licensed react-advanced-cropper with short, factual attribution. This supersedes the earlier plan for an external-library migration page; the historical studies below remain a record of past research.

## Current-API documentation decision — 2026-10-09

The project is pre-1.0 and has no external users; the maintainers are its only current consumers. Publish no migration guides, including guides for our own version upgrades. The docs and README describe only the current API; obsolete names and before/after migration examples do not belong there. The changelog records breaking changes. This supersedes the upgrade-guide requirement in D9 and the earlier allowance for documenting our own version upgrades. Historical study content remains unchanged.

## Historical decisions and retained semantics

The following 0.1.x choices are **superseded on 2026-10-09**: matching another framework's export names; component/props bags and stencil instance exports; per-part class props; public `use*` helpers; exposing `AbstractCropper`, `ArtificialTransition`, `CropperCanvas` or the implementation class; retaining deprecated wrapper `loading`/`loaded`; and requiring only Svelte `^5.29.0`. Use the decisions above. Preview snapshot `loading`/`loaded` inputs remain valid.

Still applicable:

- Deprecated cropper `stencilSize`/`autoZoom` remain removed; use `FixedCropper` and explicit `postProcess`. Framework-only state/forwarding helpers from the original implementation are not part of the Svelte API.
- [CropperController.svelte.ts](../../src/lib/controllers/CropperController.svelte.ts) uses explicit effects fed by scalar `$derived` image identities and loading status. Initialization snapshots preserve changes made during mount while skipping unchanged initial values; unchanged derived values suppress notifications. Native effect teardown owns cleanup where needed. This replaces the removed dependency-array watcher (whose historical comparisons used element-wise `Object.is`, not deep comparison).
- [CropperView.svelte](../../src/lib/components/internal/CropperView.svelte) and [CropperPreview.svelte](../../src/lib/components/preview/CropperPreview.svelte) own resize and orientation-change handling through `<svelte:window>`. Svelte installs/removes the listeners with component lifetime; callbacks invoke the current refresh operation. This replaces the removed imperative window-listener helper.
- Instance mutation methods run untracked to avoid effect feedback loops. Getter reads remain tracked. Notifications cannot fire outside the mounted lifetime; the internal engine clears its transition timer on disposal.
- Public visual/gesture primitives, `styleToString` and `fillLayoutBoundary` remain available. Internal gesture processing methods are not exposed as component exports.
- Accessibility defaults retain empty image alt text and presentation roles on gesture surfaces. Native non-passive gesture listeners use attachments.

## Tooling notes

- SvelteKit 3 removed `$lib`. Use `#lib` (package.json imports); site demos import the library by package name.
- oxlint's type-aware rules cannot see types declared in Svelte module scripts. Interfaces consumed by TypeScript files live in TypeScript files.
